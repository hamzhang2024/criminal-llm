系统概览

刑事案卷智能分析系统是一款面向刑事辩护律师的桌面应用，通过 AI 大语言模型自动完成案卷材料的文字识别、内容提取、证据分析和辩护策略生成。

核心功能

  • PDF 案卷批量上传、去水印、OCR 文字识别
  • PDF 自动转换为 Markdown 格式（MinerU 云端引擎）
  • 基于三阶层犯罪论体系的辩护分析
  • 自动生成指控要素、人物关系、事件拆解、法律法规、证据列表、矛盾分析和三阶层分析报告
  • AI 交互式辩护问答
  • 一键导出完整辩护报告

业务流程

上传 PDF
→
去水印 / OCR
→
PDF 转 MD
→
智能分析
→
辩护报告

安装与启动

系统采用前后端分离架构，需分别启动后端和前端服务。

2.1 环境要求

组件最低版本说明
Python3.13后端运行环境
Node.js18+前端构建与开发
macOS13+推荐运行平台（Apple Silicon 最佳）
poppler最新版PDF 缩略图生成（可选，通过 Homebrew 安装）

2.2 安装依赖

# 后端依赖
cd backend
pip install -r requirements.txt

# 前端依赖
cd ../frontend
npm install

2.3 启动服务

  1. 启动后端

    cd backend
python3 main.py

    后端服务在 http://localhost:8080 启动，无热重载，修改代码后需手动重启。

  2. 启动前端

    cd frontend
npm run dev

    前端开发服务器在 http://localhost:5173 启动，浏览器自动打开。

  3. 生产构建

    cd frontend
npm run build

    构建产物输出到 frontend/dist/，可部署到任意静态服务器。

ℹ️
提示：建议同时在两个终端窗口中分别运行后端和前端，以便查看日志和调试。

系统配置

首次使用前，必须配置 MinerU Token 和 LLM API Key 两个核心凭据。

3.1 打开设置页面

在首页点击右上角 ⚙️ 设置 按钮进入设置页面。

3.2 配置项说明

配置项说明默认值是否必填
MinerU Token MinerU 云端 PDF 转 Markdown 的认证凭据 — 是
LLM API Key 阿里云百炼平台的 API 密钥 — 是
LLM Base URL 大模型 API 的基础 URL https://coding.dashscope.aliyuncs.com/v1 否
LLM Model 使用的大模型名称 qwen3.6-plus 否

3.3 配置操作

  1. 填入凭据

    在表单中依次填入 MinerU Token 和 LLM API Key。

  2. 测试连接（可选）

    点击每个配置项旁边的「测试」按钮，验证凭据是否有效。

  3. 保存

    点击「保存」按钮，配置将持久化到 ~/.openclaw/criminal-llm-config.json。

⚠️
注意：首页会显示配置缺失提示。如果缺少 MinerU Token 或 LLM API Key，PDF 转 MD 和智能分析功能将无法正常工作。
4

创建案件

所有分析操作都围绕「案件」进行，首先需要创建或导入案件。

4.1 新建案件

  1. 点击「新建案件」

    在首页点击 + 新建案件 按钮。

  2. 填写案件信息

    在弹出的对话框中输入：

    • 案件名称：用于标识案件，如 "张三诈骗案"
    • 被告人姓名：案件涉及的被告人姓名（可选）

  3. 上传 PDF 文件

    选择要上传的 PDF 案卷文件，支持多选。上传后文件自动存入案件的 original/ 目录。

4.2 导入已有案件文件夹

如果已经存在符合案件目录结构的文件夹，可以一键导入：

  1. 在首页的「待导入文件夹」区域找到目标文件夹
  2. 点击 导入 按钮，系统自动扫描并注册为合法案件

4.3 案件目录结构

每个案件在磁盘上是一个文件夹，结构如下：

data/cases/{case_id}/案件_名称_日期/
├── case.json          # 案件元数据
├── original/          # 原始上传的 PDF
├── processed/         # 去水印后的 PDF
├── md/                # 转换后的 Markdown
├── md_images/         # Markdown 中的图片
├── evidence/          # 提取的证据清单
└── analysis/          # 分析报告
    ├── stage_1/       # 指控要素
    ├── stage_2/       # 人物关系
    ├── stage_3/       # 事件拆解
    ├── stage_4/       # 法律法规
    └── stage_5/       # 综合辩护

4.4 删除与回收站

删除案件后进入回收站，保留 30 天，逾期自动清除。可在回收站中恢复或立即清除。

流水线处理

案件详情页提供完整的流水线式处理流程，每一步自动加载上一步的输出。

5.1 打开案件详情页

在首页点击任意案件卡片，进入案件详情页。页面顶部显示案件基本信息，下方为处理步骤面板。

5.2 处理步骤

步骤输入输出说明
步骤 0上传 PDForiginal/保持原始文件名
步骤 1original/processed/去水印、密码移除、OCR 识别
步骤 2processed/ 或 original/md/PDF 转 Markdown
步骤 3md/analysis/三阶层辩护分析

5.3 操作方式

  • 每一步完成后自动显示完成状态和结果摘要
  • 可点击「重新处理」按钮重新执行某一步
  • 后续步骤依赖前一步完成，未完成的步骤显示为锁定状态
  • 可随时刷新页面，处理状态自动从磁盘恢复
ℹ️
设计原则：每一步自动加载上一步输出，不需要手动添加文件。文件名保持延续性，不使用 UUID 替换原文件名。
6

PDF 转 Markdown

将 PDF 案卷转换为 Markdown 格式，提取文字、表格和图片。

6.1 转换引擎

系统使用 MinerU 云端 API 作为默认转换引擎：

  • 支持扫描件 OCR 和原生 PDF 文字提取
  • 自动识别版面结构（标题、段落、表格）
  • 图片自动提取到 md_images/ 目录
  • 每日免费 1000 页，超额后需排队
  • 超时设为 1 小时（3600 秒）

6.2 操作流程

  1. 进入转换页面

    在案件详情页点击「PDF 转 MD」步骤，或从侧边栏选择「转换」。

  2. 选择文件

    系统自动列出 processed/ 目录下的所有 PDF 文件（如未处理则从 original/ 读取）。

  3. 开始转换

    点击「开始转换」按钮，后台异步执行转换任务。进度条实时显示当前阶段：

    • 排队等待中 → 上传文件 → 转换中 → 下载结果 → 完成

  4. 查看结果

    转换完成后，Markdown 文件保存到 md/ 目录，同名同目录。可在案件详情页预览。

⚠️
注意：签名行会被替换为 [手写签名] HTML 占位符，不会生成无效的图片引用。扫描件 PDF 的转换时间会比原生 PDF 更长。

6.3 断点续传

已处理完成的 MD 文件会跳过，部分处理的文件会清理后重新提取。刷新页面或后端重启后，转换进度自动恢复。

智能分析

系统核心功能 — 基于三阶层犯罪论体系，自动完成案卷的辩护分析。

8.1 分析阶段

分析分为 5 个阶段，前 4 个阶段可独立运行，第 5 阶段依赖前 4 个阶段的输出：

阶段内容依赖
阶段 1：指控要素提取案件中的指控要素，包括罪名、犯罪事实、证据类型等无
阶段 2：人物关系分析涉案人员之间的关系图谱无
阶段 3：事件拆解按时间线拆解案件事件无
阶段 4：法律法规检索适用的法律法规和司法解释无
阶段 5：综合辩护基于前 4 个阶段的输出，生成综合辩护策略阶段 1-4

8.2 分析理论框架

分析基于 三阶层犯罪论体系：

构成要件
符合性
→
违法性
→
有责性

8.3 操作流程

  1. 进入分析页面

    在案件详情页点击「案卷分析」，或在侧边栏选择「分析」。

  2. 选择分析阶段

    点击阶段卡片上的「运行」按钮。阶段 1-4 可随时运行，阶段 5 需等待前 4 个阶段完成。

  3. 查看分析结果

    每个阶段完成后，结果以 Markdown 格式展示，包含：

    • 指控要素：罪名、犯罪事实、证据类型等结构化要素
    • 人物关系：人员关系图谱（含 Mermaid 图）
    • 事件拆解：按时间线排列的事件清单
    • 法律法规：适用的法条、司法解释和参考案例
    • 综合辩护：完整的辩护策略和建议

  4. 清除重跑

    点击「清除」按钮可删除某个阶段及其后续所有阶段的分析结果，重新运行。

8.4 分析报告页面

分析完成后，可进入「分析报告」页面查看完整结果。页面包含 8 个标签卡：

指控要素

罪名、犯罪事实、证据类型等结构化提取

人物关系

涉案人员关系图谱，含 Mermaid 可视化

事件拆解

按时间线排列的事件清单

法律法规

适用的法条、司法解释和参考案例

证据列表

结构化证据清单，按类型分类

矛盾分析

证据之间的矛盾点和逻辑漏洞

三阶层分析

构成要件 → 违法性 → 有责性逐层分析

完整报告

所有阶段结果合并，支持导出

8.5 AI 交互问答

在分析报告页面，可使用 AI 交互式辩护问答功能：

  • 在底部输入框输入问题，点击发送或按 Enter
  • AI 基于已完成的分析结果回答问题
  • 支持多轮对话，上下文自动关联
  • 支持引用案卷中的具体证据材料
ℹ️
状态恢复：分析过程中刷新页面或后端重启，已完成阶段的结果从磁盘自动恢复，运行中的状态尽可能恢复。

案例检索

检索《刑事审判参考》1750 篇精品案例（含裁判要旨），勾选真实案例后重新生成法律法规分析，让报告中出现可核验的真实案号引用。

9.1 功能简介

  • 内置《刑事审判参考》1750 篇精品案例库，每篇含裁判要旨
  • 支持关键词检索与罪名筛选
  • 勾选案例后可查看全文，一键引用并重新生成「法律法规」分析
  • 重新生成的报告中将引用真实案号，替代模型自行虚构的参考案例

9.2 开通流程

  1. 申请 API Key

    前往官网 www.casefix.cn/api-access 提交申请，审核通过后 API Key 将通过邮件发送。

  2. 配置并验证

    在设置页「案例检索 API」区块粘贴 API Key，点击「验证」确认可用后保存。

  3. 开始使用

    打开报告页「法律法规」标签，底部即出现案例库检索面板。

9.3 使用方法

  1. 检索案例

    在检索面板输入关键词，或按罪名筛选，点击「检索」查看匹配案例列表。

  2. 勾选案例

    勾选需要引用的案例，点击案例可展开查看全文（含裁判要旨）。

  3. 引用并重新生成

    点击「引用选中案例并重新生成」，系统将选中案例注入阶段 4 分析，重新生成「法律法规」内容，报告中会出现真实案号引用。

9.4 配额说明

  • 每日 200 次检索配额
  • 勾选 N 篇案例重新生成会消耗 N 次配额（每篇案例需单独拉取卡片）
⚠️
注意：案例检索需要联网。案例库服务不可用时，仍可使用原有的联网版类案检索功能，不受影响。
10

分析工作流

重构后的分析流程：在控辩对抗与辩护意见之间新增「辩护思路确认」环节，律师确认方向后再生成辩护意见；同时支持编辑类案检索关键词、要件级证据标注与提取完整性校验。

10.1 分析顺序

新版分析按以下顺序推进，辩护意见生成前必须经过律师确认辩护思路：

指控要素
→
法律框架
→
证据摄入
→
综合结论
→
控辩对抗
→
辩护思路确认
→
辩护意见
  • 法律框架：汇总适用法条、司法解释与类案裁判规则（类案检索关键词可编辑，见 10.3）
  • 证据摄入：按要件摄入证据，标注每条证据与指控要件的关联（见 10.4）
  • 辩护思路确认：新增的人工确认环节，未确认前不会生成辩护意见（见 10.2）

10.2 辩护思路确认（新）

分析推进到「辩护思路确认」阶段时，系统会先生成一份《辩护思路建议》，由律师确认后再继续：

  1. 查看《辩护思路建议》

    系统基于前述分析生成建议，包含主攻方向与备选方向，每个方向附依据与风险提示。

  2. 确认面板

    案件详情页自动弹出确认面板，可勾选系统建议的思路、直接修改内容，或补充自己的辩护思路。

  3. 确认并继续

    点击确认后，系统按确认稿继续生成辩护意见。律师补充的思路优先级最高，会作为辩护意见的主线。

  4. 报告页查看与重编

    报告页新增「辩护思路」标签，展示已确认的思路定稿，可随时重新编辑后再生成辩护意见。

10.3 类案检索关键词（新）

  • 案件详情页分析区新增「类案检索关键词」编辑框
  • 默认值为 罪名 + LLM 推荐词，可直接修改
  • 关键词直接影响「法律框架」阶段的类案裁判规则检索结果，检索不准时可先调整关键词再重跑

10.4 证据提取增强

  • 要件级标注：每条证据标注其关联的指控要件（如「主观明知」「非法占有目的」），便于按要件审查证据链
  • 非证据标注：卷宗封面、目录、封底、备考表等自动标注为「非证据」，显示灰色徽标，但文件仍保留在案卷中，不会被删除
  • 完整性校验：证据列表显示绿 / 黄状态点。绿色表示提取完整；黄色表示疑似遗漏，建议人工复核对应卷宗后重新提取
ℹ️
提示：证据提取保留文件完整原始内容（含封面、目录等），不做预过滤，由模型自行判断是否构成证据，避免遗漏关键信息。

10.5 上下文自适应

系统会根据所选模型的上下文窗口大小自动调整输入预算，避免因窗口不足导致截断或失败：

  • 切换模型后自动识别其上下文窗口，并按窗口大小分配各阶段的输入预算
  • 设置页会显示识别结果（模型名称与窗口大小），可据此选择合适的模型
  • 窗口较小的模型仍可完成全流程分析，系统会自动压缩长文输入

12

常见问题

使用过程中可能遇到的问题及解决方案。

配置相关

Q: MinerU Token 从哪里获取？

A: MinerU Token 在 MinerU 官方网站注册后获取。前往 mineru.ai 注册账号并生成 API Token。

Q: LLM API Key 在哪里获取？

A: 在阿里云百炼平台（bailian.console.aliyun.com）开通服务后获取 API Key。

Q: 可以更换其他大模型吗？

A: 可以。在设置页面修改 LLM Base URL 和 LLM Model 即可。需确保目标 API 兼容 OpenAI 接口规范。

转换相关

Q: PDF 转 MD 失败怎么办？

A: 可能原因：① MinerU Token 无效或过期；② 网络连接问题；③ PDF 文件损坏。检查 Token 后重试，或尝试使用其他 PDF。

Q: 转换速度很慢？

A: MinerU 是云端服务，转换速度取决于网络状况和服务器负载。扫描件 PDF 需要额外 OCR 处理，时间会更长。

Q: 每日 1000 页用完了怎么办？

A: MinerU 每日免费限额 1000 页，超额后需排队等待。建议优先处理重要案件的 PDF，或次日再试。

分析相关

Q: 分析结果不准确怎么办？

A: 可以尝试：① 确保 PDF 转 MD 质量良好（文字识别完整）；② 更换更强的 AI 模型；③ 在 AI 问答中进一步追问和细化。

Q: 刷新页面后分析状态丢失？

A: 已完成阶段的结果从磁盘自动恢复。但如果后端进程被重启，运行中的分析任务可能丢失，需重新运行。

Q: 可以单独重新运行某个阶段吗？

A: 可以。点击该阶段的「清除」按钮，会同时清除该阶段及其后续所有阶段的结果，然后重新运行。

其他

Q: 支持 Windows 系统吗？

A: 核心功能（Python + React）跨平台兼容。但以下 macOS 特定功能需要适配：① AppleScript 文件夹选择对话框；② open 命令打开文件；③ pdftoppm 生成缩略图（Windows 需安装 poppler for Windows 或改用 PyMuPDF 方案）。

Q: 数据存储在哪里？

A: 所有数据存储在本地 data/cases/ 目录下。案件即文件夹，方便备份和迁移。配置文件存储在 ~/.openclaw/criminal-llm-config.json。

Q: 如何备份案件数据？

A: 直接复制 data/cases/ 目录到备份位置即可。每个案件是一个独立文件夹，可以单独复制迁移。

🔒
安全提醒：案件数据可能包含敏感的个人信息和法律材料。请妥善保管，不要将案件目录上传到不可信的第三方服务。

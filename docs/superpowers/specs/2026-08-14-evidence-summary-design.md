# 证据详细摘要层 — 设计文档

**日期**：2026-08-14
**状态**：已确认
**前置工作**：按份提取（`evidence_perdoc.py`，commit 7f30de5）已解决"保数量砍内容"，单份笔录全文保真

---

## 1. 背景与问题

按份提取后，证据全文保真（单份笔录 4–9K 字符，全案证据约 900 万字符）。分析阶段有两种消费方式：

- **分批发**（人物关系/逐份审查/质证）：`_batch_analyze_evidence` 按 token 预算分批，不截断单份 → 可完整消费
- **单发型**（阶段3时间线、阶段52矛盾分析）：`_truncate_all` 超预算按比例截断 → 大案下口供层自身超预算（笔录尾部被截），书证层重度截断

提取层（全量保真）与分析层（单发装不下）之间缺一层**浓缩但完整覆盖**的产物。

## 2. 目标

1. 提取完成后自动生成每份证据的**结构化详细摘要**，供单发分析阶段完整消费
2. 全文与摘要**双通道**给用户查看，预览弹层内切换
3. 摘要的保真度由**确定性校验**保障（金额/日期/人名/分账细节不丢）

## 3. 非目标（YAGNI）

- 不做独立"阅卷摘要"汇总页
- 不做按证据类型分模板（8 栏目全员保留，无内容填"无"）
- 不主动回填旧案件摘要（重新提取时自动生成）
- 不修改分批发分析阶段的消费方式（继续读全文）

## 4. 摘要结构（8 固定栏目）

无字数硬截断；事实透彻性由栏目承担，叙述只负责脉络。无内容的栏目填"无"，不省略栏目（结构稳定，利于 LLM 消费与 UI 渲染）。

| # | 栏目 | 保留内容 |
|---|------|---------|
| 1 | 概述 | 事件脉络叙述，长度随事实量自然伸缩 |
| 2 | 共谋与分工 | 谁提议/谁出资/谁执行/如何约定，逐环节保留 |
| 3 | 主观明知 | 明知内容（利率违法性、资金来源等） |
| 4 | 获利与分账 | 总获利、每人分得数额、分配方式（现金/转账/抵债）、分配时间 |
| 5 | 辩解与否认 | 无罪/罪轻辩解，**永不省略** |
| 6 | 关键事实 | 逐笔一行：时间｜主体｜行为｜金额｜利率｜资金来源｜分成 |
| 7 | 态度变化 | 供述稳定性、翻供、认罪认罚 |
| 8 | 矛盾提示 | 与其他证据的矛盾点 |

设计理由：金额日期好保留，"如何共谋/如何分工/明知什么/怎么分账"这类影响主从犯认定、犯罪数额、主观故意的质性事实最易被压缩吞没——专用强制栏目 + 校验兜底。

## 5. 架构与数据流

```
按份提取（已有）→ evidence/evid_NNN_xxx.md（全文，不动）
        ↓ 自动串联（提取完成后自动触发，再进分析）
evidence_summarizer.py（新模块，与 evidence_perdoc.py 平级）
        ↓ 每份证据一次调用；短证据（<800 字）不调 LLM，直接复制原文作 summary
        ↓ Semaphore 并发，复用 evidence_concurrency 配置（1-50）
        ↓ 保真校验（覆盖率不达标重试一次）
        ↓ 双写：index.json 每条证据的 summary 字段
        ↓       evidence/summaries/NNN_xxx.md（落盘缓存）
        ↓
分析阶段：
  单发型（阶段3时间线/阶段52矛盾分析）→ prefer_summary=True  → 消费摘要
  分批发（人物关系/逐份审查/质证）     → prefer_summary=False → 消费全文
```

### 模块职责

**`backend/evidence_summarizer.py`**（新）：
- `summarize_evidence(client, case_dir, concurrency) -> dict`：主流程，返回 `{total, done, failed, skipped}`
- `verify_summary_fidelity(full_text, summary) -> list`：确定性保真校验，返回问题列表（空=通过）
- 栏目解析与齐全性校验（8 栏目）
- 短证据判定（<800 字直接复制原文，不调 LLM）
- 断点续传（`evidence/summaries/` 落盘）与失效（证据 MD 长度/mtime 变化重生成）

**`backend/case_manager.py`**（改动）：
- `_do_extract_evidence` 完成后串联调用 `summarize_evidence`
- `clear-evidence` 同步清空 `summaries/`
- index.json 每条证据增加 `summary`、`summary_coverage_warning`（bool）字段

**`backend/analysis_engine.py`**（改动）：
- `_load_evidence_texts(prefer_summary: bool)` 加显式参数：
  - `True`：优先 index.json 结构化字段（含 summary），无摘要回退全文
  - `False`：读全文 MD（现状）
- 阶段3、阶段52 传 `True`；阶段2、5A、质证传 `False`

**前端**：
- `components/EvidencePreview.tsx`（新共用组件）：顶部「摘要 | 全文」分段切换，默认摘要；摘要按 8 栏目渲染（MacOS 设计系统）；`summary_coverage_warning` 显示黄色标记；无摘要回退全文不报错
- 案件详情页证据列表「预览」、报告页证据中心，均换用该组件

## 6. 保真校验（确定性）

仿按份提取的校验思路（机器检查，不靠 LLM 自觉）：

1. **实体覆盖率**：从全文抽取所有金额（含"分给某人 N 元"分账表述）、日期、人名 → 检查在摘要中的出现率，阈值 90%
2. **栏目齐全性**：8 个栏目标题必须全部出现
3. 不达标 → 带问题清单重试一次 → 仍不达标 → 保留摘要 + `summary_coverage_warning: true`，不静默丢全文

## 7. 并发与断点续传

- 复用 `evidence_concurrency` 配置（设置页 1–50），`asyncio.Semaphore`，`llm_client` 全局限流兜底
- 成本估算：全案约 200 份证据（其中需调 LLM 的约半数）× 单次 10–20 秒，并发 3 约 10–20 分钟
- 每份摘要落盘 `evidence/summaries/`，中断/重启只补缺的
- 证据 MD 长度或 mtime 变化 → 该份自动重生成
- 短证据（<800 字）不调 LLM，直接复制原文作 summary（无压缩需求，避免过度结构化）

## 8. 错误处理

| 场景 | 行为 |
|------|------|
| 单份摘要 LLM 调用失败 | 按 llm_client 网络重试 + 业务层重试一次 → 仍失败标记失败，分析端回退该份全文 |
| 校验两轮不达标 | 保留摘要 + 警告标记，前端可见 |
| 摘要步骤整体异常 | 不阻塞分析启动（分析端全部回退全文，等同现状） |
| 旧证据无 summary | UI 回退全文显示；分析端回退全文 |

## 9. 测试

**单元测试**（`tests/test_evidence_summarizer.py`）：
- 8 栏目齐全性校验
- 实体覆盖率计算（金额/日期/人名/分账金额）
- 覆盖率不达标 → 重试 → 警告标记
- 短证据跳过（<800 字直接复制原文，不调 LLM）
- 断点续传（已有摘要+MD 未变 → 跳过；MD 变化 → 重生成）

**集成测试**：
- 提取→摘要串联（mock LLM）：index.json 写入 summary 字段
- `_load_evidence_texts(prefer_summary=True/False)` 双层切换正确
- clear-evidence 同步清空 summaries

**真实验证**：
- 冯叶飞案第2卷（29 份证据）跑摘要，人工抽查共谋与分工/获利与分账栏目是否保留细节

## 10. 成功标准

- 冯叶飞案全案摘要总量 ≤ 25 万字符（单发预算 125 万字符内，余量 5 倍）
- 阶段52 矛盾分析输入不再触发 `_truncate_all` 截断
- 摘要保真校验：金额/日期/人名覆盖率 ≥ 90%（未达标的证据有警告标记）
- 前端预览可在摘要/全文间切换，无摘要旧证据正常显示全文
